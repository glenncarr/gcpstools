# Contributing to gcpstools

## Repository structure

```
gcpstools/
├── .github/workflows/publish.yml   # CI/CD for PowerShell Gallery
├── src/gcpstools/
│   ├── Private/                    # Internal helper functions
│   ├── Public/                     # Exported functions
│   ├── gcpstools.psd1              # Module Manifest
│   └── gcpstools.psm1              # Root Module Script
├── tests/                          # Pester tests
├── build.ps1                       # Local build/test script
├── CHANGELOG.md
├── LICENSE
└── README.md
```

## Development

```powershell
# Import the module from source
Import-Module ./src/gcpstools -Force

# Run tests
./build.ps1 -Test
```

> Note: `Get-SlackChannelHistory` has `#Requires -Version 7.0`, so the module
> must be imported under PowerShell 7 (`pwsh`), not Windows PowerShell 5.1.

## Build script (`build.ps1`)

`build.ps1` drives local building, testing, versioning, and releasing. All
switches are independent and can be combined (for example
`./build.ps1 -Analyze -Test`).

| Switch | Description |
| --- | --- |
| `-Test` | Installs Pester 5+ if needed and runs the Pester suite in `tests/`. |
| `-Analyze` | Installs PSScriptAnalyzer if needed and lints `src/gcpstools`. Throws if any **Error**-severity findings are reported. |
| `-Import` | Imports the module from source with `-Force -Verbose`. |
| `-Publish` | Copies `README.md` into the module folder and publishes to the PowerShell Gallery using the `PSGALLERY_KEY` environment variable. Normally done by CI, not locally. |
| `-BumpVersion <Major\|Minor\|Patch>` | Increments `ModuleVersion` in the manifest (comments/formatting preserved) and rolls the CHANGELOG `[Unreleased]` section into a dated release heading. Does **not** commit, tag, or push. |
| `-Tag` | Creates the annotated git tag `v<ModuleVersion>` and pushes it to `origin`, which triggers the publish workflow. Requires a clean working tree and prompts for confirmation (bypass with `-Confirm:$false`). |

### Public function conventions

Each file in `src/gcpstools/Public/` must define exactly **one** function whose
name matches the file name (approved verb-noun). Helper functions belong in
`Private/` or nested inside the public function. When you add a public
function, also add its name to `FunctionsToExport` in `gcpstools.psd1` — that
list is the authoritative export filter used by both the manifest and CI.

## Releasing a new version

Releases are published to the PowerShell Gallery by the tag-triggered workflow
in `.github/workflows/publish.yml`. Pushing a `v*` tag makes CI verify the tag
matches the manifest `ModuleVersion`, run the Pester suite, and publish.

1. **Bump the version** — updates the manifest and CHANGELOG:

   ```powershell
   ./build.ps1 -BumpVersion Patch   # or Minor / Major
   ```

2. **Review and commit** the version bump and CHANGELOG entry:

   ```powershell
   git add src/gcpstools/gcpstools.psd1 CHANGELOG.md
   git commit -m "Release v0.1.10"
   git push
   ```

3. **Tag and push** to trigger the publish workflow:

   ```powershell
   ./build.ps1 -Test -Tag           # runs tests, then tags + pushes
   ```

   `-Tag` refuses to run against a dirty working tree, will not overwrite an
   existing tag, and prompts before pushing (pushing a tag starts the Gallery
   publish and is hard to undo). To tag manually instead:

   ```powershell
   $v = (Import-PowerShellDataFile ./src/gcpstools/gcpstools.psd1).ModuleVersion
   git tag -a "v$v" -m "v$v"
   git push origin "v$v"
   ```

## Publishing

The published Gallery README is generated by copying the root `README.md` into
the module folder at publish time (see `build.ps1 -Publish`). Do not commit
`src/gcpstools/README.md` — it is git-ignored and produced on demand.
